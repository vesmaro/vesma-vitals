# D-0001: Два контура измерения — health для каждой функции, value только по обещанию

Дата: 2026-09-09 · Статус: принято (ArchCom, vesma `7ec9dda3` + `061398fe`) ·
Контекст: директива владельца «методика должна охватывать ВЕСЬ функционал сервера»

## Решение

Каждая функция сервера получает обязательный health-контур (вызывается / успешно /
латентность / ошибки — инварианты и коридоры). Value-контур (доказанная польза,
вердикты) строится только для функций с продуктовым обещанием. «Каждая функция
измерена» ≠ «каждая функция value-измерена»: value рождается из обещания, не из
покрытия; без компаратора value-вопрос не существует.

## Почему

- Директива «весь функционал» в лоб означала бы value-метрики для ~85 методов —
  месяцы работы ради vanity-чисел. Двухконтурность закрывает весь функционал дёшево
  (health — счётчики на границах) и концентрирует дорогое (стенды, judge) там, где
  есть обещание.
- Владелец читает два разных вопроса: «работает ли» (health-светофор F9) и «что мне
  это даёт» (value-светофор F8). Смешение сделало бы оба ответа нечитаемыми.

## Альтернативы отвергнуты

| Альтернатива | Причина отказа |
|---|---|
| Value-метрики для каждой функции | Value без компаратора — переименованные счётчики; то, чем владелец недоволен сейчас |
| Health-only без value | Оставляет вопрос владельца «сколько экономим» без ответа — провал директивы |
| Три контура (usage отдельно) | Вызываемость входит в health; «стоит ли функция издержек» — в value-вердикты |

## Последствия

Правило «ни одна функция не едет в релиз без своего контура» становится
инженерным гейтом mnemos-vitals. Value-семейство не расширяется без новой
директивы владельца.
