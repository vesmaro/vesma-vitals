# Препрегистрация эксперимента S5 «memory-value» (v1, синтетика)

Дата препрегистрации: 2026-09-22 · Статус: **ЗАМОРОЖЕНА до первого прогона**
Канон: methodology.md §1.3 (анти-HARKing), §3.5; ADR-0025 E0-шаблон (vesmaro);
архитектура §5. Гейт: этот файл коммитится ДО первого прогона S5. Изменения
после первого прогона запрещены; новое окно порогов = новая препрегистрация.

## Вопрос владельца (директива 2026-09-09, 0fd16319)

«Сколько токенов реально экономим за счёт грамотного формирования контекста?»
Заголовок «экономим X» валиден ТОЛЬКО при равной успешности ног
(task_success(M) ≥ task_success(B0-naive)) — зеркало equal-budget канона.

## Гипотезы (до данных)

- **H1 (экономия)**: net_savings(M) > 0 — нижняя граница бутстрепного CI95
  (10 000 ресэмплов, сессионный бутстреп, стратифицированный) строго > 0.
- **H2 (не хуже)**: task_success(M) ≥ task_success(B0-naive) − δ,
  δ = MDE-зеркало (10 пп); иначе заголовок экономии НЕ печатается.
- **H3 (против «убийцы красивых слов»)**: task_success(M) ≥
  task_success(B0-file) − δ B0-file (файл равного среднего бюджета).
- **H4 (guardrail динамичности)**: context_dynamism_ratio ≥ препрегистрированный
  минимум (см. «Пороги»); доля внутрисессионных пар с нулевой
  dynamic_uniqueness ≤ U_max.

## Метрики (одна величина — одно имя — одно семейство, F8)

- `gross_savings = prompt_tokens(B0-naive) − prompt_tokens(M)`
- `write_cost = Σ traces(tokens_in + tokens_out)` по write-path сессии
- `net_savings = gross_savings − write_cost`; `value_ratio = net_savings /
  prompt_tokens(B0-naive)`; `tokens_per_success`
- `context_dynamism_ratio = 1 − static_share` (статический блок := тот же
  keyed-HMAC отпечаток в ≥ 80% сборок сессии); `dynamic_uniqueness =
  mean(1 − Jaccard(HMAC-шинглы))` по парам запросов сессии (пары сэмплируются
  при > 20 сборках, seed фиксирован: blake2b(session_id))
- `replay-fp-rate = 1 − relevance` (relevance = доля задач, где judge подтвердил
  релевантность использованных блоков; в v1 — retrieval-score-прокси ≥ 0.35)

## Дизайн

- **Ноги** (симметричный репортинг, убрать пост-фактум нельзя):
  M (memory-on, mnemos assemble_context), B0-naive (полный транскрипт в окне),
  B0-file (статический курируемый файл равного среднего бюджета), B0-full
  (вся история — справочно, завышает экономию; в вердикты не входит).
- **Изоляция**: каждый рукав — копия стора (SQLite backup API, actor=benchmark);
  wall-clock в метрики не входит; детерминизм — BLAKE2b lexical embedder.
- **Корпус v1**: синтетика ~100 задач × 3 страты (факт-вставка / правило-запрос /
  многоходовая сессия) + 20 негативных (задачи, где память помогать не должна —
  деградация M на них = сигнал wallpaper-памяти).
- **Пороги коридоров**: от первого прогона baseline − max(0.02; CI95);
  пороги вердиктов фиксируются в этом файле после baseline-прогона и ДО
  решающего прогона (окно «порог после baseline, не до данных»).

## Анализ

Медианы по сессиям (не пулы) + бутстреп CI95 + p25/p75, по стратам.
McNemar для парных task_success M vs B0-naive. Ошибка множественности:
все H — одна предрегистрированная семья, поправка Холма.
**Single-look**: решающий прогон один; промежуточные — только для
инженерии (латентность), не для выбора порогов.

## Честность отчёта

PASS/FAIL/NO-DATA; NO-DATA ≠ ноль, никогда не зелёный. Генератор при breach
аварит (exit 1), не редактирует. Workload-фингерпринт (BLAKE2b workload.jsonl)
печатается в отчёте; comparator-ноги симметричны; исключить ногу пост-фактум
нельзя. Вердикты никогда не блокируют мержи; инварианты и коридоры — блокируют.

## КАППА-АБЛЯЦИЯ (2026-09-25) — touched_rate НЕ коридорная метрика в v1

Препрегистрация `docs/experiments/touched-rate-kappa.md` исполнена
(решающий look, single-look исчерпан): T=50 стратифицированных ходов,
истина — абляцией (блок «истинно релевантен» ⇔ его удаление роняет
task_success 1→0), предикт — touched-эхо стенда. **Оцениваемых блочных
решений — 0**: на S5-ленте максимум 25 токенов/блок против канона ≥ 40
(сигнальный домен пуст) → κ не существует → вердикт громкий NO-DATA
(H-K0): `touched_rate` — НЕ коридорная метрика в v1, `corridor_eligible:
false` структурно. Перекалибровка = НОВАЯ препрегистрация (корпус с более
крупными блоками). Деградировавший touched_share несёт причину prereg
(гейт мягко заперт для оператора). B0-file negative-stratum failure — recipe artifact
(дисклеймер в отчёте).
