# Шаблон эксперимента (препрегистрация / отчёт)

Конвенция каталога `docs/experiments/`: препегистрация фиксируется **до** первого
прогона (анти-HARKing); отчёт — дата в имени файла, сырые выдачи — `raw-data.md`
рядом. Этот шаблон — скелет обоих. Обязательные секции помечены **[обязательно]**;
пропуск обязательной секции = отчёт невалиден (в т.ч. секция «Экономия токенов» —
директива владельца 2026-10-04, словарь величин — [../token-economy.md](../token-economy.md)).

## 1. Вопрос и гипотеза

Один фальсифицируемый вопрос владельца. Гипотеза с предсказанием числом
(«граф закрывает T2/T3 одним вызовом»), а не «проверим, как работает».

## 2. Метод **[обязательно]**

- Объект (репо/сервер/версия, состояние индекса/стора на старте: узлы/рёбра/файлы,
  fresh %, poisoned);
- задачи/нагрузка и их происхождение (реальная сессия, страты, негативный контроль);
- стороны сравнения и счётчик токенов (провайдерский `usage` / chars/4);
- что считаем (вызовы, время, размеры выводов, дочитывания); фиксация команд
  (воспроизводимость: точные rg-паттерны, аргументы вызовов).

## 3. Базлайн **[обязательно]**

Явный базлайн каждой стороны сравнения (grep-мир / полный-контекст /
предыдущая модель — словарь: [../token-economy.md](../token-economy.md) §2в).
Смена базлайна после прогона = новая препегистрация.

## 4. Результаты

Таблица по задачам: сторона A / сторона B / исход. Числа измеренные; оценки — с
пометкой и формулой. Сырьё — в `raw-data.md`.

## 5. Экономия токенов **[обязательно — ДО вердикта]**

Чек-лист секции (словарь и формы — [../token-economy.md](../token-economy.md)):

1. Счётчик: <провайдерский usage | chars/4>; дата замера.
2. Аренда `R` варианта: <ток/сессию> (метод замера: tools/list-сериализация /
   иная); аренда базлайна: <ток или «0 — bash-тул и так в контексте»>.
3. tokens-per-task `T` по задачам обеих сторон: `R/N + args + outputs +
   follow-ups`; равные слагаемые исключены с пометкой.
4. Экономия против базлайна: `savings = T_baseline − T_variant`, одно предложение
   с числами; отрицательная — как отрицательная.
5. Break-even `N*` и амортизационная таблица `N ∈ {1, 5, 10, 50}` (если `R > 0`).
6. Помеченные оценки перечислены явно.

Минимальная строка-вердикт секции: «экономия <варианта> против <базлайна> на
типовой задаче: <X> ток (<Y>%), break-even N* ≈ <Z>».

## 6. Вердикт и последствия

Только после секции 5. Что родилось из замера (PR/релизы/инструкции), какие
проигрыши чем закрыты. Вердикт без заполненной секции 5 — невалиден.

## 7. Протокол повтора

Когда и каким критерием повторять; куда писать данные.

## 8. Ограничения

Окно данных, одна инсталляция / синтетика, дрейф состояний между замерами — что
именно ограничивает силу выводов.
