# Токен-экономика — метрика №1

Дата: 2026-10-04 · Статус: канон оценки сравнений (директива владельца) · Владелец:
Tech Lead · Словарь величин: этот документ · Причинное доказательство экономии
памяти: S5 по [methodology.md](methodology.md) (F3/F8)

**Директива владельца (2026-10-04):** экономия токенов (= деньги) — **оценочная
метрика №1 во всей методологии сравнения/оценки моделей и инструментов**. Без
показателя экономии красивые слова не значат ничего для целевой группы (агенты и
операторы, платящие за токены). Отсюда правило валидности:

> **Вердикт любого сравнения (модели, инструмента, метода, поверхности) без строки
> экономии — невалиден.** Строка экономии обязана стоять **до** вердикта в отчёте;
> отрицательная экономия печатается как отрицательная (см. §1, правило честности).

## 1. Честность измерения

Те же три правила, что в основной методологии, в приложении к токенам:

1. **Токены — канон, деньги — конверсия.** Все измерения и вердикты — в токенах.
   Денежная строка опциональна: `$ = tokens × price_per_token` по актуальному
   прайсу провайдера, с датой прайса. Цены плавают — токены не плавают. Пример
   конверсии помечать «иллюстрация».
2. **Счётчик.** Канонический счёт — из ответа провайдера (`usage.prompt_tokens` /
   `completion_tokens`). Когда ответа нет (текстовые дампы, схемы, диффы),
   консервативная оценка — **chars/4** (канон MCP-аудита 2026-10-03); она же —
   сопоставимый межинструментальный стандарт этого репозитория. Смешивать счётчики
   в одной таблице запрещено; используемая оценка указывается в шапке таблицы.
3. **Оценки помечаются.** Каждое число в отчёте — измеренное или с пометкой
   «оценка» с формулой оценки. Бесспорных «примерно» не бывает.

## 2. Определения (строгие, измеримые)

### (а) Schema rent — аренда схем инструментов

**`R = Σ tokens(serialize({name, description, inputSchema}))` по всем тулам
сервера в манифесте клиента за сессию.**

Сериализация — `json.dumps` каждого тула так, как его отдаёт `tools/list` (метод
MCP-аудита 2026-10-03, воспроизводим скриптом). Аренда лежит в контексте **всегда**
— каждый промпт сессии несёт манифест целиком, даже при нулевом использовании.
Манифест all-or-nothing: клиент платит за все тула сервера, а не за вызываемые.
Пример (vesma, замер 2026-10-04): весь манифест 39 тулов ≈ 44 247 симв ≈ **11 061
ток/сессию**; граф-контур (10 тулов ADR-0032) ≈ 9 353 симв ≈ **2 338 ток**; при
этом бенчмарк graph-vs-grep реально вызывал только `search_graph` + `trace_path`
≈ 702 ток — остальные 1 636 ток граф-контура стояли в холостую (см. §5).

Базлайн «grep-мир» считает аренду CLI нулевой **маржинально**: bash-тул и так есть
в контексте любой сессии. Чтение `--help` — не аренда, а discovery-стоимость (§2г).

### (б) tokens-per-task — полная стоимость задачи

**`T = R/N + Σ(args) + Σ(outputs) + Σ(follow-ups)`**, где

- `R/N` — амортизированная аренда (N — число задач сессии, делящих манифест);
- `Σ(args)` — токены аргументов всех вызовов инструмента задачи (то, что модель
  генерирует);
- `Σ(outputs)` — токены всех выводов инструментов (то, что модель читает);
- `Σ(follow-ups)` — дочитывания файлов после поиска, вызванные неполнотой ответа
  (Read/сниппеты). Слагаемые с равным значением у обеих сторон сравнения
  исключаются с явной пометкой (пример: чтение тела найденной функции одинаково в
  граф- и grep-мире).

Каждое слагаемое измеряется; оценочные (например, «агент дочитает ~5 сайтов по
~30 строк») — с пометкой и формулой.

### (в) savings vs baseline — экономия против явного базлайна

**`savings = T_baseline − T_variant`** (может быть отрицательной — печатается).

Базлайн **явный на каждое сравнение**, из фиксированного набора:

| Базлайн | Когда применять |
|---|---|
| **grep-мир** (CLI: rg/ls/--help + парсинг текста) | сравнение инструментов поиска/навигации по коду |
| **полный-контекст** (B0-naive: весь транскрипт/файл в окне) | сравнение методов формирования контекста |
| **предыдущая модель** (предыдущая версия той же роли) | сравнение моделей |

Смена базлайна между черновиком и вердиктом = смена вопроса; фиксируется в
препрегистрации (анти-HARKing, §1.3 основной методологии).

### (г) break-even — окупаемость аренды

**MCP-тул vs CLI-вызов: `N* = R / discovery_cost_per_cli_use`**, где
`discovery_cost` — стоимость разового CLI-пути: чтение `--help`/man + парсинг
текстового вывода. Замеры-ориентиры (2026-10-04): полный `rg --help` ≈ 74 678
симв ≈ **18 664 ток** (эпизодично, но одно такое чтение дороже аренды всего
граф-контура на 8 сессий); парсинг сырого вывода — на **каждое** использование.

Общая форма (когда CLI-путь не отвечает на задачу в принципе или отвечает
дороже): **`N* = R / Δvar`**, где `Δvar` — измеренная переменная экономия
варианта против базлайна на одной задаче (§4). Правила:

- `Δvar ≤ 0` → `N* = ∞`: аренда не окупается никогда, вариант проиграл
  в этом сценарии;
- частота использования в реальных сессиях (`N_факт`) сравнивается с `N*`:
  `N_факт ≥ N*` → MCP; `N_факт < N*` → CLI/REST.

### (д) Амортизационная таблица — обязательная форма

Для любого варианта с ненулевой арендой: `cost(N) = R + N·var` против базлайна
`N·var_baseline`, минимум при `N ∈ {1, 5, 10, 50}`, с колонкой дельты. Пример —
ретрофит graph-vs-grep ([experiments/graph-vs-grep-20261003.md](experiments/graph-vs-grep-20261003.md)).

## 3. Правило строки экономии

Чек-лист валидного сравнения (всё — в отчёте ДО вердикта):

1. счётчик указан (провайдер / chars/4);
2. `R` аренды варианта измерен, базлайн аренды объявлен;
3. `T` для обеих сторон, по задачам (не только среднее — среднее маскирует
   разброс, как T2/T4 в graph-vs-grep);
4. базлайн явный (§2в);
5. `N*` и амортизационная таблица (если `R > 0`);
6. строка «экономия …» одним предложением с числами;
7. оценки помечены.

Шаблон эксперимента с обязательной секцией: [experiments/TEMPLATE.md](experiments/TEMPLATE.md)
(секция «Экономия токенов» — до вердикта).

## 4. Поверхностная политика MCP-vs-CLI — следствие метрики

Метрика превращает спор «MCP или CLI» в арифметику окупаемости аренды:

| Класс тула | Частота (N_факт на сессию) | Решение | Числа из аудита vesma (2026-10-03) |
|---|---|---|---|
| Рабочий корень агента (save/search/recall) | десятки | **MCP** — аренда амортизируется | 85 % вызовов телеметрии; аренда доли ≈ 3 928 ток |
| Граф-контур (поиск/трейс по коду) | единицы–десятки | **MCP** при дисциплине вызовов (kind/limit) | аренда 2 208–2 338 ток; N* ≈ 9 задач/сессию (ретрофит) |
| Ops/lifecycle (reindex, export/import) | ~0 у агента | **CLI/REST** — MCP-аренда в холостую | DR-1: reindex в MCP стоил бы ~400–500 ток/сессию при нулевом телеметрическом спросе |
| Алиасы/дубли в манифесте | 0 | дроп из манифеста | `tags_rename` — алиас, 6.0 дропает; watch_* → группировка, ~0.4k ток |

Следствия, зафиксированные числами:

- **Slimming = прямая экономия.** Аудит: манифест 10.9k ток → цель ≤ 7k (DR-2,
  description-diet + schema-diet + группировка). Каждый 1k ток аренды × тысячи
  сессий = деньги без единого изменения поведения.
- **Гранулярность аренды — дефект all-or-nothing.** Бенчмарк использовал 2 тула
  из 10 граф-контура, платя за все 10 (+1 636 ток в холостую); за всё сервера
  (11 061) платит любая сессия, даже grep-only. Аргумент за opt-in компактный
  манифест / lazy tools (п. 3.3 аудита) — измеряется той же метрикой.
- **Discovery-цена CLI не бесплатна.** `rg --help` ≈ 18 664 ток за одно полное
  чтение; парсинг текстового вывода — на каждый вызов. Для редких тулов это
  дёшево (эпизод), для частых — дороже аренды MCP: граница и есть `N*`.

Правило для новых тулов vesma: кандидат в MCP проходит оценку
`N_факт(ожидаемая) ≥ N*` на телеметрии до попадания в манифест; иначе — CLI/REST
с документированным исключением (прецедент DR-1).

## 5. Отношение к основной методологии

- Словарь этого документа — общий для **всех** сравнений (модели, инструменты,
  методы), не только памятных: S5/F8 доказывает причинную экономию памяти
  двухрукавным replay; этот док задаёт единицы и формы строк для любого отчёта.
- Зона 1 основной методологии (токен-экономика) остаётся каноном для
  `net_savings`/`value_ratio`; здесь определены переиспользуемые примитивы
  (аренда, tokens-per-task, N*), которыми зона 1 пользуется как словарём.
- `chars/4` — стандарт этого репозитория (аудит 2026-10-03 → ретрофит
  2026-10-04); при переходе на провайдерские счётчики пересчитать обе стороны
  сравнения одним счётчиком.
