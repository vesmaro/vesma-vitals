## 1. Принцип честности

Методология обязана уметь напечатать «это не работает». Все механизмы ниже подчинены
этому: вердикты могут быть красными, отсутствие данных — громкое, пороги фикируются
до измерений. Отчёт, который не умеет краснеть, — не отчёт, а маркетинг.

Три правила честности:

1. **Две плоскости измерения.** Пассивный прод-сбор меряет факты (стоимость
   инжекций, состав, использование). Причинная ценность («сколько токенов
   сэкономлено») доказывается **только** двухрукавным replay-стендом S5 с
   comparator-ногами. Заявление «экономим X» из пассивных данных — ложь
   инструментализма, запрещена.
2. **Таксономия статусов** — ядро честности:

   | Статус | Что это | Merge-гейт | Отчёт владельца |
   |---|---|---|---|
   | Инвариант | Механический факт (= 1.000 / = 0) | блокирует всегда | отдельная строка |
   | Коридор | Регрессия к собственному baseline (− max(0.02; CI95)) | блокирует | красный при выходе |
   | Вердикт | Порог ценности на replay / живых сессиях | **никогда** не блокирует | PASS / FAIL / NO-DATA |

   NO-DATA ≠ ноль ≠ пропуск строки; никогда не зелёный. Продвижение вердикта в
   merge-гейт — только новой директивой владельца с перепрепрегистрацией. Бремя
   доказательства лежит на памяти: PASS по экономии ⇔ нижняя граница бутстрепного
   CI95 (95%-й доверительный интервал) net-token-savings строго > 0.
3. **Препрегистрация до прогона** (анти-HARKing, канон E0 из ADR-0025 mnemos):
   гипотезы, comparator-ы, пороги, workload-фингерпринт, план анализа, single-look
   фиксируются в `docs/experiments/` **до** первого прогона. Порог выбирается после
   baseline, не до данных; для value — полная препрегистрация; для health — только
   правило «порог после baseline».

## 2. Двухконтурная рамка (аддендум «весь функционал»)

| Контур | Вопрос | Правило охвата | Статусы |
|---|---|---|---|
| **Health** | Работает ли функция? | **Каждая** функция сервера: 26 MCP-инструментов, ~50 REST-маршрутов, ~8 фоновых jobs, workflow, auto-collect, CLI, doctor. «Ни одна функция не едет в релиз без своего контура». | инварианты + коридоры |
| **Value** | Что функция даёт? | Только функции с продуктовым обещанием; метрики ложатся в существующие семьи-владельцы. | вердикты (не блокируют) |

Value-метрики и их семьи-владельцы (правило «одна величина — одно имя — одно семейство»):

| Величина | Семья-владелец |
|---|---|
| CCR-redemption, context_rewrite-redemption (маркер выкуплен / оригинал восстановлен) | F3 Token economy |
| auto-collect adoption, checkpoint-return | F5 Session coherence |
| refine-качество (McNemar paired raw-vs-refined + refine-retention-gain ≥ 0) | F2 Accuracy |
| auth-bypass-probe (пробу исполняет S4-механика) | F6 Availability |
| федерация-value (когда появится клейм, по новой директиве) | F8 Memory value |
| net-token-savings, value_ratio, tokens_per_success, relevance_judge_rate, replay-fp-rate, touched_rate, context_dynamism_ratio, explicit_hint_share, dynamic_uniqueness | F8 Memory value |

**F10 не заводится** — ни одной величины без семьи-владельца. Правило границы семейств:
семейство = тема или один фальсифицируемый вопрос владельца, **никогда ярус**
(«value» — не тема). Новое семейство ⇔ нет существующей семьи-владельца И директива
владельца ставит один вопрос со своим компаратором. Прецедент рождения — F8.

## 3. Зоны и порядок (ядро методики)

Пять зон, порядок реализации **4 → 1 → 2 → 5 → 3** (динамичность первой — почти
бесплатно на существующих выходах `assemble_context`, ловит страх владельца):

1. **Токен-экономика.** `gross_savings = prompt_tokens(B0-naive) − prompt_tokens(M)`;
   `write_cost = Σ traces(tokens_in + tokens_out)` по write-path;
   `net_savings = gross − write_cost`; `value_ratio = net / prompt_tokens(B0-naive)`;
   `tokens_per_success`. Заголовок «экономим X» валиден только при
   `task_success(M) ≥ task_success(B0-naive)` (равная успешность — зеркало
   equal-budget канона ADR-0025). Отчёт: медиана по сессиям + бутстрепный CI95 + p25/p75,
   по стратам, не пулом.
2. **Релевантность инжекций.** Лестница сигналов: retrieval score → shingle-touched
   (блоки ≥ 40 токенов; в коридоры только после калибровки каппой Коэна ≥ 0.6 против
   абляции ~50 ходов) → слепой LLM-judge (двойная разметка, каппа в отчёте).
   `replay-fp-rate = 1 − relevance`. Деградационный алерт: explicit_hint_share
   высокий + dynamism ≈ 0 → RED (recall игнорирует запрос — дословно страх владельца).
3. **Маршрутизация инструкций/скиллов.** Wrong-tool A/B: ~100 парных задач + ~20
   негативный контроль, McNemar p<0.05, MDE +10 пп абсолютных. Поверх протокола
   ADR-0025 E3 — не дублировать. Последняя по порядку.
4. **Динамичность контекста.** Серверный `context_dynamism_ratio = 1 − static_share`
   (статический блок := отпечаток в ≥ 80% сборок сессии);
   `dynamic_uniqueness = mean(1 − Jaccard(HMAC-шинглы))` по парам запросов внутри
   сессии (пары сэмплируются при длинных сессиях); `explicit_hint_share` —
   метрика-предусловие. Структурный фальсификатор: доля внутрисессионных пар с нулевой
   уникальностью превышает препрегестрированный уровень → FAIL. Харнесный слой
   `prompt_static_share` (доля статического в полном промпте) — информационный,
   клиентский, никогда не гейтит регрессии mnemos (атрибуция невозможна).
5. **Стенд S5 «memory-value».** Двухрукавный replay: memory-on / memory-off на
   изолированной копии стора (SQLite backup API, прецедент S4; wall-clock в метрики
   не входит). Comparator-ноги: **B0-naive** (полный транскрипт в окне — заголовок),
   **B0-file** (статический курируемый файл равного среднего бюджета — «убийца
   красивых слов»), **B0-full** (вся история — только справочно, завышает).
   Скриптованная нога ~100 задач × страты + ~20 негативный контроль; replay-нога
   ≥ 30 сессий (50 — цель). Симметричное репортингование ног (убрать пост-фактум
   нельзя), workload-фингерпринт, single-look, генератор отчёта exit-1 при breach
   (аварит, а не редактирует).

## 4. Семейство F9 «Subsystem health»

Единственное новое семейство, health-only **навсегда** (не принимает value — иначе
свалка). Суб-светофоры обязательны: строка на подсистему, иначе красный не
actionable. Состав:

| Подсистема | Метрики |
|---|---|
| Федерация | pull-success-rate, bytes-synced, acl-denied-rate; инвариант federation-acl-probe = 1.000 (контрольные пробы вне scope получают deny) |
| Workflow | инвариант workflow-transition-validated = 1.000; forbidden-attempt-rate, stale-lock-rate, blocked-age p50/p95 |
| Heal / reclaim | effectiveness, fail-rate, recovery (счётчики уже считаются в коде mnemos — экспонирование почти бесплатно) |
| DLQ | retry-success-rate, age-of-oldest |
| ingest_url | success-rate, placeholder-rate, ssrf-rejected; инвариант ingest-ssrf-bypass = 0 |
| Auth | 401/429-rate per endpoint-шаблон; инвариант auth-bypass-probe = 1.000 |
| Транспорт | MCP/REST traffic split, per-tool гистограмма (какие из 26 инструментов реально используются) |
| Scanner | per-detector hit-rate (class + pattern; никогда matched text) |
| Watchers / jobs | events-indexed, lag, cycle-duration |
| Doctor | health.check-история: динамические проверки hourly, упавшая = FAIL-строка, отсутствие ожидаемой строки = алерт (missingness ≠ здоровье) |
| CCR-механика | инвариант ccr-marker-accounting = 1.000 (issued = redeemed + expired_ttl + evicted_lru + active) |

Волны реализации: (1) молчаливые отказы + бесплатные счётчики (heal/reclaim/refine-outcome,
CCR-accounting, федерация, workflow), (2) auto-collect/ingest/401/429/DLQ-retry/MCP-split
(после петли использования), (3) слепая выборка quarantine-FP (n=30/нед, порог ≤ 0.05
препрегестируется до первой выборки), refine-McNemar (ждёт корпус 192), federation-value
(по owner-directive).

## 5. Security-контур (унаследован и расширен)

- **C1**: канареечный тест изоляции — bug-report / backup / export / federation пути
  **не включают** metrics.sqlite; канарейка — первый коммит, до появления метрик;
  перечисляет все таблицы явно.
- **C2**: паритет прав/шифрования с основным стором (0600, encryption-at-rest тем же PR).
- **C3**: config-lint — per-request сбор при `auth_enabled=true` отказывается стартовать
  без явного подтверждения; verb-таблицы не имеют session/principal-колонок — навсегда.
- **C4**: retention TTL fail-loud (ночной DELETE + VACUUM; отказ джобы = алерт);
  метрики объявлены «не аудит-записи».
- **C5** (аддендум): `meta_json` — allowlist fail-closed; неизвестный ключ = отказ записи
  с warning; текст исключений / стектрейсы / caller-input — никогда.
- **RL-S1** (P0, тикет mnemos #249): `_METRICS_BYPASS` — /metrics и /api/v1/metrics
  обходят auth безусловно даже при `auth_enabled=true` на non-loopback и уже
  экспортируют by_project/by_agent. Чинится **первым шагом** до любой новой exposition.
- **RL-S2–S7**: публичная exposition — ноль лейблов endpoint/project/detector;
  нигде principal/session/peer-id/IP/concrete-path/user-agent/per-request security-строки;
  инварианты вычисляются из гейтов/канареек/тестов, не из non-fatal телеметрии
  («0 в телеметрии» не доказывает «0 утечек»); fail-loud — только инварианты + слепота
  монитора; attacker-driven счётчики (401/429/SSRF/ACL) — коридоры с дедуплицированными
  тикетами, никогда per-event алерты (иначе противник топит оператора); наружу —
  rates с знаменателями per-day.

## 6. Claims-ledger

`docs/claims.md` (в репозитории mnemos-vitals, зеркалируется в README-утверждения
mnemos): каждое обещание README/features → семья-владелец → метрика → статус
(`measured-value` / `measured-health` / `UNMEASURED`). Флагманские строки: CCR
«оригиналы сохранены» → F3 redemption (вторая половина обещания сегодня недоказана);
«KV-кэш попадает» → UNMEASURED (нужен клиентский сигнал). Правило сиротской метрики:
метрика без дашборда / алерта / claims-ссылки удаляется на квартальном ревью.

## 7. Фазы

| Фаза | Что | P / размер | Гейт |
|---|---|---|---|
| A | metrics sink + пассивный сбор (3 таблицы assemble-домена) | P1 / S | C1-канарейка зелёная до первой метрики |
| A2 | verb-леджер + rollup (весь функционал) + Prometheus-гибрид + C5 + фикс #249 | P1 / M | канарейка на 5 таблиц; INSERT p95 < 2 мс в hooks-пути; факт объёма/день; retention зелёная |
| B | динамичность + S5 v1 (синтетика) + F8-светофор + retention | P1 / M | препегистрация закоммичена ДО первого прогона |
| C | петля использования (post_llm_call-аннекс: touched/cited/wrong_tool) | P2 / S | touched откалиброван каппой ≥ 0.6 против абляции |
| D | replay реальных сессий | P3 / S→M | opt-in per capture + санитизация fail-closed на границе |
| E | wrong-tool A/B (зона 3) | P3 / M | поверх протокола ADR-0025 E3, McNemar |
| F9-волны 1–3 | семейство здоровья | P2–P3 | коридоры от измерений (2 недели baseline) |
| doctor-P3 | health.check-история | P3 | гарды: FAIL-строка на упавшую, алерт на пропуск |

Порядок: A → A2 → B (A2 не блокирует B, но фундамент один) → C → D → E.
Прогонная среда стендов — K3s-кластер владельца (devops-dev-cluster), манифесты в
универсальной директории `~/LABs/**/` (вердикт Round-4 v2), обучение моделей — всегда
в контейнере nano-llm/XPU.
